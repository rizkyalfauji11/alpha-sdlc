## Screen scaffolds & layout patterns

> The app's recurring **screen anatomy** — the scaffold a screen instantiates, so every screen of the
> same kind is composed the same way (this is what makes the app feel like one product; without it each
> screen re-derives its layout from its own mockup and they drift apart). **Learn it from the existing
> screens** (describe); where the app is inconsistent, flag the contradiction and establish the intended
> pattern with the user (prescribe). Grooming binds each screen to a scaffold (widget-spec `Scaffold`
> field); `do-development` builds from it (reuse the code component when one exists); `do-testing`
> asserts conformance. New patterns are **registered here on create** — never invented per screen.

| Scaffold | Anatomy (top → bottom) | Body slicing | Dividers & spacing (token names) | Responsive behavior | Code component (if any) |
|----------|------------------------|--------------|----------------------------------|---------------------|-------------------------|
| <feature-page> | <header: title `title.screen` + description `body.sm` + **actions top-right** → horizontal divider → body> | <e.g. 1:2:1> | <`divider.hairline` (full-bleed) between header/body · header→body `space.lg` · section gap `space.xl` · edge padding `space.lg`> | <columns stack below `<breakpoint>`> | <`PageScaffold` — or "none; pattern only"> |
| <detail-page> | <header (title + back + actions) → body → sticky footer actions> | <1:3> | | | |
| <settings-page> | <title → grouped sections, no actions> | <single column> | | | |

> Every value in *Dividers & spacing* is a **token name from
> [design-tokens](./18-design-tokens.md)**, never a raw number — including divider thickness and whether
> it's inset or full-bleed. A scaffold that carries loose numbers is a scaffold each screen re-guesses.

**Slicing vocabulary:** <the ratios the app uses (e.g. 1:2:1 · 1:3 · 1:2:2) and when each applies — so "how do we split this screen" is a lookup, not a per-screen invention.>

**Header anatomy (the standard):** <what every feature header carries — title (which typography role), description, where actions go (e.g. top-right), what's optional — and the divider token + gap token between header and body.>
