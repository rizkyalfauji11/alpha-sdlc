> The locator contract. The app's **widget-spec Test IDs** are the only first-class locator — they're
> a *contract* the app maintains (`do-development` applies them; IDs are never renamed once shipped),
> which is what makes regression tests survive UI refactors.

## Locator hierarchy

1. **Widget-spec Test ID** (primary, always) — from the feature's `widget-spec/<screen>.md` in the app repo.
2. **Accessibility role + name** (only for elements a widget spec legitimately doesn't cover, e.g. framework chrome).
3. **Never:** visible text, CSS structure/order, XPath — brittle locators are how suites rot.

## Per-platform attribute mapping

| Platform | Test ID applied as | Located via |
|----------|--------------------|-------------|
| Web | `data-testid` | <e.g. `getByTestId`> |
| Android | `resource-id` (View `android:id` / Compose `testTag` + `testTagsAsResourceId`) | <UiAutomator/Espresso matcher> |
| iOS | `accessibilityIdentifier` | <XCUITest query> |

## When an ID is missing

<A needed element with **no Test ID** is an **app gap, not a QA workaround**: route it back to the feature's widget spec (the app adds the element + convention-following ID per `do-grooming`/`do-development` rules) — never invent a brittle locator to move on. Track pending ID requests here or in the issue tracker.>

## Selector ownership

<Locators live **only in screen-objects** (`02-test-architecture.md`) — one screen, one file, one place to fix when a screen changes. Specs and flows never contain raw selectors.>
