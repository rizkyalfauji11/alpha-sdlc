## Locator hierarchy

1. **Discovered stable test ID** (primary) — `data-testid` (web) · `resource-id` (Android) · `accessibilityIdentifier` (iOS), as found on the built app.
2. **Accessibility role + name** — when a screen carries no test IDs; **flagged as fragility** in the screen-object.
3. **Never:** visible text, CSS structure/order, XPath — brittle locators are how suites rot.

## When a screen has no stable IDs

<The standing ask: **request test IDs from the app's dev team** (list the screens/elements needing them — a one-line attribute per element on their side buys locator stability forever). Until provided: role+name fallback, the screen-object marked fragile, and the request tracked here or in the tracker. Never block a needed test on the ask — but never pretend a text locator is stable either.>
